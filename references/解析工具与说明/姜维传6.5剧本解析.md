# 姜维传 6.5pl 剧本解析

剧本来源：`bin\Release\RS\`，共 127 个 EEX 文件（R_xx = 剧情/城内场景，S_xx = 战场）。
抽取工具：`eex_story.py`（`uv run python eex_story.py <RS目录> <输出目录>`），输出在 `story_out\*.txt`。
共抽出约 4 万句对话。

## 一、EEX 字节结构（依据 src/script_vm.c、script_run.c、script_cmd.c）

```
+0x00  "EEX\0"
+0x04  ver = 01, sub = 02
+0x06  记录链 {int16 type, uint16 len, data[len]}，type 0 表示链结束（本作首条就是 00 00 00 00）
       链尾即 tableOff（本作为 0x0A）
tableOff: DWORD 形式的 Section 偏移表，首项值同时就是表尾位置，块数 = (首项 - tableOff) / 4
Section:  WORD 头 + 记录 { WORD len, 指令流 }
指令:     WORD opcode + 参数...
参数:     WORD tag + 值；tag 4 = DWORD，tag 5 = GBK 字符串（以 \0 结尾），其余 tag 均为 WORD
          (FetchArg(1) 读的是裸 WORD，不带 tag，只出现在 0x05 变量测试的下标列表里)
          tag 不符时取参器返回哨兵 0x8000/0x80000000，指令返回 5
6.5 扩展:  tag 2/0x38/0x39 的 WORD 值落在 0xEFFF~0xFFFE 时，表示整型变量 IntVar[(~w)-1]；
          tag 4 的 DWORD 为负且 opcode<=0x6D 时，表示 IntVar[-v]
控制流:    0x01 子事件 → 紧跟一条条件指令(0x04/0x05/0x25/0x3F…) → WORD len + 子体(以 0x00 结束)
          条件不成立时由 ScriptAdvance 读出 len 后整体跳过
```

剧情相关 opcode 及参数 tag 序列：

| op | 名称 | 参数 |
|---|---|---|
| 0x14 | 对话 | [5] 文本内嵌 `&姓名\n台词`，多段之间用 `\n&` 分隔 |
| 0x15 | 对话2 | [2 说话者, 2 对象, 5 文本] |
| 0x16 | 信息 | [5] |
| 0x17 | 场所名 | [5] |
| 0x18 | 事件名 | [5] |
| 0x19 | 胜利条件 | [5] |
| 0x12 / 0x13 | 选择框 / case | [5 选项(以\n分隔), 2] / [4 选项号] |
| 0x2C | 地图文字 | [5, 0x26 x, 0x26 y, 0x26 style] |
| 0x63 | 单挑对话 | [0x26 方位, 5, 0x26] |
| 0x67 | 章名 | [4 章号, 5 标题] |
| 0x69 | 旁白 | [5] |
| 0x11 | 剧本跳转 | [0x37 场景号]：编号 0 对应 S_00，2n-1 对应 R_n，2n 对应 S_n |

文本控制码：`[C29…]` 表示变色，`*/4033` 表示插入 IntVar[4033] 的值。

## 二、流程与分支

- 场景顺序：R_00(开局设定 + 序幕) → S_00 → R_01 → S_01 → … 每对 R/S 构成一关。
- **分支点在 R_32 第 1 节「命运的决断」**（剑门关，钟会来信，张嶷/诸葛果提议防守阴平）：
  - 选「派遣军队去防守（进入幻想线）」：跳转到场景 67，即 R_34「偷渡阴平/汉之星彩」。之后是 S_34 … R_57/S_57，最后到 R_58，通关幻想线。
  - 选「不派遣军队防守（进入历史线）」：R_33（投降之议、北地王殉国、邓艾受降、成都之战）→ S_33 成都之战（撑到 15 回合）→ 历史线结局。
- R_58 结尾提示「本周目通关幻想线」，随后跳转到 139，即 R_70（新周目开局，内容是 R_00 的副本）。
- 跳转号 117/119/121/123/125 分别对应 R_59 策略技能学习、R_60 装备淬炼、R_61、R_62、R_63 仙蕴果使用，属于功能型 R 场景；179 对应 R_90 战前准备（大地图营帐）。
- R_000（2026-04-26）是钟会营帐「雨夜密谋 / 酒中试探 / 月下独白」，属于后加的钟会之乱前奏。`新特技系统.eex` 和 `R_00 - 副本.EEX` 不是正式剧本。

## 四、已知局限

- 抽取器按「opcode + 期望 tag 序列」做模式扫描，不是完整的反汇编器。条件、子事件结构、出场设定等非文本指令都被忽略，极少数情况下可能误命中。
- 0x15 对话2 的说话者只输出武将编号（#id），没有映射成名字；0x14 的说话者名称直接取自文本。
- 战场里像「邓艾1」这样带数字后缀的说话者，是剧本里的姓名串原样（编号形式的战场说话者），没有展开。
